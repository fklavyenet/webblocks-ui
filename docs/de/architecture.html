Architektur

WebBlocks UI ist bewusst in Schichten aufgebaut, damit Tokens, Struktur, sichtbare Bausteine und ganzseitige Kompositionen nicht ineinander verschwimmen.

Das aktuelle Layer-Modell

foundationTokens und Theme-Achsen
Diese Schicht definiert Tokens, Dark Mode, Presets, Accent-Sets, Radius, Density, Shadow, Font, Border, Reset, Regeln auf Element-Ebene sowie das Standard-Styling für rohes HTML wie Überschriften und Code.
utilitieskleine Hilfsklassen
Nutze Utilities für kleine Anpassungen, wenn die wesentlichen Pattern- und Primitive-Entscheidungen bereits stimmen. Helfer für Abstände, Textgrößen, Ausrichtung, Farbe und Sichtbarkeit liegen hier.
layoutContainer und struktureller Fluss
Diese Schicht enthält Container, Stack, Cluster, Split, Grid, Row/Column, Navbar, Sidebar und Shell-Struktur. Sie löst Rahmen und Fluss, nicht UI auf Button-Ebene.
primitives + surfacesControls und gerahmte Inhaltsbereiche
Buttons, Formulare, Tabellen, Dropdowns, Drawers, Modals und Tabs sind Primitives. Cards, Stats, Callouts, Listen, Toolbars, Filter-Bars und Empty States sind Surfaces. Die öffentliche Einordnung folgt der UI-Rolle, nicht dem Ordnernamen.
patternsKompositionen auf Screen-Ebene
Patterns definieren echte Seitenaufgaben wie Dashboard Shell, Auth Shell, Settings Shell, Content Shell und Marketing-Flächen.
iconsAsset-Schicht
Icons werden in diesem Guide als klassenbasierte Assets und Aliase ausgeliefert. Sie unterstützen Primitives und Patterns, statt eine eigene UI-Schicht zu bilden.

Die Build-Reihenfolge ist entscheidend

Die Build-Reihenfolge des Pakets ist bewusst gewählt. Spätere Schichten setzen voraus, dass frühere Schichten bereits vorhanden sind.

  1. foundation
  2. utilities
  3. layout
  4. primitives
  5. patterns
  6. icons
Das Layer-Modell nicht verflachen Wenn eine Klasse in erster Linie Seitenstruktur definiert, gehört sie in layout oder patterns. Ist sie ein atomares Control, gehört sie in primitives. Ist sie ein gerahmter Inhaltsbereich, behandle sie als Surface. Verschiebt sie nur Abstände oder Textausrichtung, gehört sie in utilities.

Was diese Website bewusst nicht tut

Keine eigenen Klassen

Jede in docs/ verwendete Klasse stammt aus dem ausgelieferten Paket-CSS.

Keine Style-Skripte

Layout, Abstände und Darstellung bleiben CSS überlassen. Es wird kein JavaScript ergänzt, um CSS-Aufgaben nachzubilden.

Kein Verhalten in CSS

Overlays, Tabs, Drawers, Dropdowns und Theme-Umschaltung nutzen ausgelieferte JavaScript-Hooks statt CSS-Hacks.
