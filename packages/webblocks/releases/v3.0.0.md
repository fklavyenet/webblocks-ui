# WebBlocks UI v3.0.0 — Semantic detail lists

**Withdrawn release. Use [v2.40.0](v2.40.0.md) instead.** The supported v2 line
preserves existing div/span styling while adding all three native description
list presentations. The published v3.0.0 tag contents remain unchanged; the
notes below describe that historical release only.

Detail lists now require native HTML semantics and support three presentations.
This is a major release because div/span-only detail lists are no longer styled.
Consumers pinned to v2 remain on their existing behavior until they upgrade.

## Breaking change: migrate before upgrading

`wb-detail-list` belongs on a `dl`, `wb-detail-label` on a `dt`, and
`wb-detail-value` on a `dd`. Each direct `div.wb-detail-row` groups one term
followed by one description; the div remains a grouping wrapper only.

Inventory roots and dynamically generated templates that use `wb-detail-list`,
`wb-detail-label`, `wb-detail-value`, or `wb-detail-value-mono`. Choose a native
description list or table for each use before changing the pinned asset tag.
Do not add ARIA roles, JavaScript repair, or local CSS to preserve div-only
markup. Existing semantic `dl` consumers must also adopt the documented grouped
anatomy and review the updated typography and column proportions.

Before (unsupported in v3):

```html
<div class="wb-detail-list">
  <div class="wb-detail-row">
    <span class="wb-detail-label">Draft</span>
    <span class="wb-detail-value">Unpublished content.</span>
  </div>
</div>
```

After (native term/description association):

```html
<dl class="wb-detail-list">
  <div class="wb-detail-row">
    <dt class="wb-detail-label">Draft</dt>
    <dd class="wb-detail-value">Unpublished content.</dd>
  </div>
</dl>
```

Keep multiple paragraphs or multiple values for the same term inside its `dd`.
Use `dd.wb-detail-value.wb-detail-value-mono` for machine strings where needed.

## Three presentations, one semantic structure

| Classes on the `dl` | Presentation |
| --- | --- |
| `wb-detail-list` | Horizontal, with row separators (default) |
| `wb-detail-list wb-detail-list--borderless` | Horizontal, without row separators |
| `wb-detail-list wb-detail-list--stacked` | Term above an indented description, without row separators |

Choose one presentation. Both horizontal forms stack at viewport widths of
640 px or less. The stacked description retains an inline-start indent in LTR
and RTL. Normal terms and descriptions share the standard text size; terms use
medium weight. Monospace descriptions retain their smaller code-like sizing.
No WebBlocks JavaScript is required for any presentation.

## Use tables for tabular summaries

Field/value table summaries, including installation and assignment summaries,
use `table.wb-table`, native row headers and `td` values. Comparable records and
column-based datasets also stay in tables. For example:

```html
<div class="wb-table-wrap">
  <table class="wb-table" aria-label="Assignment summary">
    <tbody>
      <tr>
        <th scope="row" class="wb-table-key">Subject</th>
        <td>Mathematics</td>
      </tr>
      <tr>
        <th scope="row" class="wb-table-key">Attempts</th>
        <td>4</td>
      </tr>
    </tbody>
  </table>
</div>
```

Give tables an accessible name using a caption, `aria-labelledby` or
`aria-label`. Read-only summaries need no invented `Actions` column.
Description lists can express term/description and independent name/value
associations, including suitable metadata. A detail page name, visual columns
or separators alone do not determine which element to use.

## Adopting the release

1. Migrate consumer templates, adapters and dynamically generated markup.
2. Update all loaded WebBlocks assets and the downstream AI contract to the
   explicit `v3.0.0` tag. Keep the stylesheets, runtime and icons on the same pin.
3. Verify all three appearances, long terms and values, 640 px stacking,
   light/dark themes, RTL indentation and accessible table/description-list
   semantics. Check that unrelated native description lists remain unchanged.

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/fklavyenet/webblocks-ui@v3.0.0/packages/webblocks/dist/webblocks-ui.css">
```

The pinned AI contract is
[`dist/ai/contract.md`](https://cdn.jsdelivr.net/gh/fklavyenet/webblocks-ui@v3.0.0/packages/webblocks/dist/ai/contract.md).
English, Turkish and German admin examples now show all three description-list
presentations and native installation-summary tables. Integration guides and
AI contracts include the migration and the table/description-list distinction.

The AI examples source is now consistently named `ai/examples.md`, fixing
canonical builds and exports on case-sensitive filesystems.

## Validation

The dependency-free browser fixture covers source and built CSS at 320, 640,
641 and 960 px, in light/dark and LTR/RTL, including wrapping, nested lists,
monospace values, separator policy and rejection of old div-only anatomy.
Run `packages/webblocks/tests/detail-list.html` and repeat with `?source=1`.
The canonical build, table checks, CSS formatter checks, localized markup and
generated AI manifest checksums are also verified for the release.
