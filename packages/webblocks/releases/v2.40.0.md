# WebBlocks UI v2.40.0 — Compatible semantic detail lists

Continue the supported v2 line with native description lists and three visual
presentations. Existing div/span detail lists retain their v2.39.2 appearance;
upgrading from v2 does not require an immediate template migration. The
incompatible v3.0.0 release and its tag have been removed. Use v2.40.0 and pin
that tag explicitly for all assets and the downstream AI contract.

## Existing markup continues to work

This legacy structure remains styled with its original column widths, muted
small labels, row separators and mobile stacking:

```html
<div class="wb-detail-list">
  <div class="wb-detail-row">
    <span class="wb-detail-label">Draft</span>
    <span class="wb-detail-value">Unpublished content.</span>
  </div>
</div>
```

Div/span-only detail lists are deprecated for authoring new interfaces. Keeping
their CSS preserves compatibility; it does not give them description-list
semantics. No ARIA or JavaScript repair is added. Removal of this compatibility
support would require a future breaking release.

## Native markup for new and rewritten interfaces

```html
<dl class="wb-detail-list">
  <div class="wb-detail-row">
    <dt class="wb-detail-label">Draft</dt>
    <dd class="wb-detail-value">Unpublished content.</dd>
  </div>
</dl>
```

Keep a `div.wb-detail-row` only as the grouping wrapper for one `dt` followed by
one `dd`. Multiple paragraphs or values for the same term belong inside that
`dd`. `wb-detail-value-mono` remains available for machine strings.

| Classes on the native `dl` | Presentation |
| --- | --- |
| `wb-detail-list` | Horizontal with separators |
| `wb-detail-list wb-detail-list--borderless` | Horizontal without separators |
| `wb-detail-list wb-detail-list--stacked` | Term above an indented description without separators |

The two horizontal native forms stack at 640 px or less. The stacked form uses
logical inline-start indentation in LTR and RTL. No WebBlocks JavaScript is
needed. These modifiers describe native `dl` presentations; legacy div/span
markup retains its historical presentation.

## Table or description list

Use native `table.wb-table` for field/value table summaries, such as installation
and assignment summaries, and for comparable records. Use
`th[scope="row"].wb-table-key` and `td` for key/value rows, provide an accessible
table name and omit an `Actions` column when there are no row actions.

Description lists express term/description or independent name/value
associations, including suitable metadata. A page name, two visual columns or
separators do not determine which HTML structure to use. English, Turkish and
German examples and AI rules now distinguish new semantic markup from legacy
compatibility support.

## Upgrade

1. Pin all WebBlocks assets and the downstream AI contract to `v2.40.0`.
2. Keep existing templates working and migrate them when they are rewritten.
3. Use native description lists or tables for all new interfaces.
4. Verify legacy layout and native variants at desktop/mobile widths, in
   light/dark themes and LTR/RTL.

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/fklavyenet/webblocks-ui@v2.40.0/packages/webblocks/dist/webblocks-ui.css">
```

The pinned AI contract is
[`dist/ai/contract.md`](https://cdn.jsdelivr.net/gh/fklavyenet/webblocks-ui@v2.40.0/packages/webblocks/dist/ai/contract.md).

## Validation

The dependency-free browser fixture verifies source and built CSS, legacy
div/span geometry and typography, all three native presentations, 320/640/641/960
px layouts, light/dark themes, RTL indentation, long values and nested lists.
Run `packages/webblocks/tests/detail-list.html` and repeat with `?source=1`.
